## Alignment (p.17-19)

### A-21 Align elements on shared axes for order and polish  (p.17)
- **Rule**: Alignment = arranging text, images and components along common lines/axes to create visual order and harmony. Poor alignment looks messy and is hard to use.
- **Why**: Gives a polished, organised look; misalignment hurts readability and perceived quality.
- **Do / Don't**: Intro to the following two examples (A-22, A-23).
- **Audit check**: Do left edges of titles, body text, buttons, icons within a component fall on the same x line (unless intentional hanging icon)? Check computed left offsets/padding.
- **Restyle fix**: Snap all items to common axes (see A-22 - A-28).
- **Severity**: medium ; **Tags**: [alignment, layout, craft]

### A-22 Don't misjudge alignment: icon, title, body and button should share a clean edge  (p.17)
- **Rule**: Alignment can be wrong by misjudgement: aligning things incorrectly (e.g. text indented next to an icon so the body and button no longer line up with the title).
- **Why**: Incorrect alignment creates a ragged, messy card.
- **Do / Don't**: Bad (thumbs-down, left card "Cactus"): title "Cactus" at left edge; below it a round cactus icon at the left edge with paragraph and "Learn more" pill button indented to the right of the icon, so the body/button don't align with the title. Good (right card): icon and title in one row at the top; paragraph and "Learn more" button below, both flush left on the same left edge as the icon.
- **Audit check**: In cards, does body/button left edge equal title/icon left edge? Is an icon floated alongside a multi-line paragraph, causing text indentation?
- **Restyle fix**: Put icon + title in a header row; place body text and button below on the card's common left edge.
- **Severity**: medium ; **Tags**: [alignment, cards, layout]

### A-23 Don't forget to align items: list items must share left/right edges  (p.18)
- **Rule**: Bad alignment also happens when you forget to align things properly; list items need identical edges.
- **Why**: Staggered edges look sloppy.
- **Do / Don't**: Bad (thumbs-down, dark "Resources" list with dashed guideline overlay): pill items "All", "Illustrations", "UI resources", "Icons" have different left/right edges and different offsets of icon and label (staggered by a few px, from visual). Good (right): all four pills share the same left and right edges, icons share an x-axis, labels share an x-axis.
- **Audit check**: Menu/list items: identical `x` and `width`, same icon column x, same label x. Compare bounding boxes in Figma/DOM.
- **Restyle fix**: Use one container with consistent padding and `flex-col` with `align-items: stretch`; same icon size & gap.
- **Severity**: medium ; **Tags**: [alignment, navigation, layout]

### A-24 Left-align most text, especially long text and lists  (p.18)
- **Rule**: Left alignment is the go-to for most text; it creates a clean left edge that's easy to read, especially for paragraphs and lists.
- **Why**: Clean, consistent starting edge speeds reading.
- **Do / Don't**: Text guidance only.
- **Audit check**: Paragraphs/lists with `text-align: center` or right (in LTR).
- **Restyle fix**: Set `text-align: left` (`text-left`) for body text and lists.
- **Severity**: medium ; **Tags**: [alignment, typography]

### A-25 Right-align numbers (and RTL languages)  (p.18)
- **Rule**: Right alignment suits numbers such as prices or table data because values line up from the right, making comparisons at a glance easier. It's also the correct alignment for RTL languages like Arabic.
- **Why**: Easier value comparison.
- **Do / Don't**: Text guidance only.
- **Audit check**: Numeric table columns left-aligned or centred; decimals/digits not lining up; use of `tabular-nums`? (the latter not mentioned; only right alignment).
- **Restyle fix**: `text-align: right` (`text-right`) on numeric columns (and their headers); RTL pages use right alignment.
- **Severity**: medium ; **Tags**: [alignment, tables, typography]

### A-26 Centre-align only short, standout items (titles, CTAs), never long text  (p.18)
- **Rule**: Centre alignment works for things that need to stand out, like titles or call-to-action buttons; avoid it for longer text blocks.
- **Why**: Starting point of each line changes, so eyes work harder to track the text.
- **Do / Don't**: Text guidance only.
- **Audit check**: Centre-aligned paragraphs with more than ~1-2 lines (threshold not specified in PDF).
- **Restyle fix**: Switch multi-line centred copy to left alignment; keep centring for headings and button labels.
- **Severity**: medium ; **Tags**: [alignment, typography]

### A-27 Use a layout grid to align elements consistently  (p.19)
- **Rule**: Implement a grid system to make aligning easier and keep consistency across different parts of the UI.
- **Why**: Grids give shared columns and gutters.
- **Do / Don't**: Example: Figma "Layout grid" overlay (pink FF17BE at 17% opacity columns) behind three cards ("Alignment", "Visual hierarchy", "Proximity"), each card sitting exactly in one column. Settings: Columns, Count: 3, Colour: FF17BE 17%, Type: Stretch, Width: Auto, Margin: 79, Gutter: 70.
- **Audit check**: Do element widths/left edges match a column+gutter grid? Are margins/gutters consistent across sections? Check for a defined container/grid (CSS grid, Tailwind `grid-cols-*`, Figma layout grid).
- **Restyle fix**: Define a column grid (count, margin, gutter) and snap components to columns.
- **Severity**: medium ; **Tags**: [alignment, layout, spacing]

### A-28 Use auto-layout so elements stay placed correctly  (p.19)
- **Rule**: Auto-layout ensures every element sits exactly where it should without manual nudging.
- **Why**: Avoids manual alignment errors.
- **Do / Don't**: Text guidance only.
- **Audit check**: Are positions set by absolute offsets/manual nudges (absolute positioning, manual margin hacks) instead of flex/grid/auto-layout and consistent gap?
- **Restyle fix**: Rebuild with Figma auto-layout / CSS flex/grid with consistent padding and gap tokens.
- **Severity**: low ; **Tags**: [alignment, layout, craft]

## Alignment (tail of chapter) (p.20)

### B-01 Pick one alignment strategy and apply it consistently across similar elements  (p.20)
- **Rule**: Choose an alignment strategy (e.g. everything left-aligned) and stick with it across similar elements so the design feels cohesive. Do not mix left and centre alignment inside the same component.
- **Why**: Consistent alignment creates a cohesive feel; mixing strategies looks accidental.
- **Do / Don't**: Dark-mode product card, same content in both. **Don't** (thumbs-down, labelled "Alignment: Left & Center"): the rating line and the author/brand line are centred while image edge, title and the price/"Add to basket" row are left-aligned, so the dashed alignment guides don't line up. **Do** (thumbs-up, labelled "Alignment: Left"): image, rating, title, author, price and button row all share the same left edge (dashed left guide runs straight down). (from visual) The top of the page also shows a Figma Auto-layout panel on a "Task progress" card (Copywriting 3/8, Illustrations 6/10, UI design 2/7 with coloured progress bars): vertical direction, gap **24**, horizontal padding **32**, vertical padding **32** – i.e. auto-layout is a way to keep spacing/alignment consistent (from visual; the page text does not explain it).
- **Audit check**: Within one card/section, do text blocks use more than one `text-align` (left + center) or different x-origins for siblings? Look for `text-center` on some children and `text-left` on others in the same container; flag mixed alignment among similar elements.
- **Restyle fix**: Pick one alignment (default left for text-heavy UI) and apply it to every sibling in the component; remove stray `text-align:center`/`items-center` on individual children. Use auto-layout/flex with fixed gap and padding tokens (example from visual: gap 24, padding 32).
- **Severity**: medium ; **Tags**: alignment, layout, craft

## Whitespace (p.25-29)

### B-13 Give elements room to breathe with whitespace  (p.25, p.26)
- **Rule**: Whitespace ("negative space") is the unmarked area between design elements; it need not be white – any colour, texture or background image free of other elements counts. It gives room to breathe, enhances readability, guides focus and breaks up a page. Lack of whitespace makes an interface feel cramped and confusing.
- **Why**: Even when fonts, positions and colours are identical, whitespace alone can make or break the design.
- **Do / Don't**: Two "Tasking" app sidebars with identical fonts/positions/colours (Dashboard [active, tinted pill]; ANALYTICS: Performance, Mixpanel; SUPPORT: Tickets, Agents, Customers; SHOP: Products, Orders, Reports). **Don't**: items packed tightly, small padding around the active pill, tight gaps around section labels and dividers, so the list fits in less height. **Do**: more padding around logo, active pill larger with more inner padding, larger row height, and clear space around section labels/dividers; the whole list is taller, so fewer items are visible in the frame. (from visual)
- **Audit check**: Measure gaps between rows/groups: are list-item heights and group gaps clearly distinct, or do sections run together? Flag nav/list rows with vertical padding that is visually tight and group dividers with ~no margin.
- **Restyle fix**: Increase row height/padding and add larger gaps between groups than within groups.
- **Severity**: high ; **Tags**: spacing, layout, navigation

### B-14 Start with too much space, then scale down  (p.26, p.27)
- **Rule**: Start with more whitespace than you think you need, then reduce gradually until the balance is right.
- **Why**: Generous space gives flexibility to scale down. Starting with too little means you may not notice the clutter, resulting in a design hard to look at and navigate. (Over-generous space also isn't the final answer – it's a starting point.)
- **Do / Don't**: "Customer growth" card (line chart with "Total customers 179" tooltip, bars: Canada 88%, Greece 67%, France 43%, Pakistan 28%, "See more" button). p.26 shows two thumbs-down states: a loose version (large gaps between chart and rows, between rows, and before the button) and a cramped version (chart, rows, and button squeezed together, tooltip overlapping the title area). p.27 shows loose = thumbs-down, **balanced** version (moderate gaps – tighter than loose, clearly more than cramped) = thumbs-up. (from visual)
- **Audit check**: Are there crowded groupings (rows < ~8px apart (inference), chart tooltip colliding with title, button touching content)? Also flag the opposite: huge gaps that disconnect related items.
- **Restyle fix**: Increase spacing first to a generous level, then step down along the spacing scale until groups are clear but related items still read as related.
- **Severity**: medium ; **Tags**: spacing, layout, craft

### B-15 Establish a spacing and sizing system on a base unit  (p.28)
- **Rule**: Choose a base unit and work in multiples of it. Example: multiples of 4 → 4px, 8px, 16px, 24px, 32px, and so on. Systems based on multiples of 2, 4 or 6 are fine.
- **Why**: A standardised system gives consistent look and feel, speeds up design adjustments while keeping everything proportional, and reduces cognitive load because users' eyes/brain don't have to adjust to new spacing rules.
- **Do / Don't**: Contact form "Let's level up together" (subtitle "You can reach us anytime via hello@uxpeak.com", fields First name / Email / Message, checkbox "You agree to our friendly privacy policy.", "Send message" button). **Do** (thumbs-up): measured gaps annotated **16, 40, 8, 24, 24, 24, 40** (title→subtitle 16; subtitle→first field 40; label→input 8; between fields 24; between message and checkbox 24; checkbox→button 40) – all multiples of 8/4, with the same value reused for the same relationship. **Don't**: gaps **7, 19, 8, 19, 19, 21, 19** – arbitrary values with inconsistent relationships. (from visual; PDF text lists 16, 40, 40, 8, 24, 24, 24 and 7, 19, 19, 19, 19, 8, 21)
- **Audit check**: Extract all margin/padding/gap values; flag any not on the chosen grid (e.g. not multiples of 4). In Tailwind, flag arbitrary values like `p-[19px]`, `mt-[7px]`; in Figma flag spacing not from tokens.
- **Restyle fix**: Snap all spacing to the nearest scale step (4/8/16/24/32/40…); define spacing tokens; reuse one value per relationship type.
- **Severity**: high ; **Tags**: spacing, craft, layout

### B-16 Tie the spacing system to the Law of Proximity (fixed value for related items)  (p.29)
- **Rule**: With a multiples-of-4 system, fix a rule such as "related items are 8px apart" and apply it throughout; larger steps separate unrelated groups.
- **Why**: Easy to apply consistently; simplifies cognitive load; aligns with Law of Proximity.
- **Do / Don't**: See B-15 (label→input always 8; fields apart 24; sections apart 40).
- **Audit check**: Is the gap within a group (e.g. label→input) always smaller than the gap between groups, and is the same value used everywhere for the same relationship?
- **Restyle fix**: Define tokens: e.g. intra-group 8px, between-field 24px, between-section 40px (values from visual of the form) and apply consistently.
- **Severity**: medium ; **Tags**: spacing, hierarchy, layout

### B-17 Avoid random, non-multiplicative spacing numbers  (p.29)
- **Rule**: Don't use arbitrary spacing such as 31px or 19px.
- **Why**: Odd non-multiplicative numbers throw off harmony, disrupt rhythm, make the interface feel disjointed, and are harder to remember and reapply consistently.
- **Do / Don't**: Bad form from B-15 uses 7, 19, 21 etc.
- **Audit check**: Search CSS/Tailwind/Figma for spacing values like 7, 19, 21, 31px (not divisible by the base unit 4).
- **Restyle fix**: Round to the nearest scale value (e.g. 19→16 or 20/24, 31→32, 7→8).
- **Severity**: medium ; **Tags**: spacing, craft

## Layout (p.30-34)

### B-18 Treat layout as both aesthetics and usability  (p.30)
- **Rule**: Layout is about not just what elements are on screen but where and how they're placed; it's the framework bringing aesthetics and usability together. Good layout (1) is visually pleasing, catching the eye and setting up a positive experience; (2) is intuitive, guiding the user logically through tasks so they find what they need.
- **Why**: As stated.
- **Do / Don't**: See B-19.
- **Audit check**: Does the visual flow (top→bottom / left→right) match the task order? Can users locate key info on first scan?
- **Restyle fix**: Re-arrange blocks into a logical reading order with clear grouping.
- **Severity**: medium ; **Tags**: layout, hierarchy

### B-19 Prefer a simple single-column layout with a large hero image and generous whitespace over a cramped horizontal row separated by lines  (p.30, p.31)
- **Rule**: When showcasing a product/food item, use a simple single-column layout with a large eye-catching image and generous whitespace instead of cramming image, price and button in one small row separated by divider lines.
- **Why**: Visual appeal drives restaurant/food decisions ("we eat with our eyes"); a large appealing image makes the food look more premium and gives the perception of greater value. The streamlined design lets users scan multiple options quickly without getting bogged down in details.
- **Do / Don't**: Pizza card ("Italian pizza with tomato and salami", "$12 / 1 pizza", "Order now", description "Our authentic Italian pizza is made with the freshest ingredients and cooked to perfection."). **Don't**: wide card where the name is the most prominent element on top, then a row with small pizza thumbnail | price | orange Order-now button divided by vertical lines, with horizontal rules, and description in small text at the bottom. **Do**: narrow card with large pizza image on top, centred name, small grey description, price, full-width orange Order-now button, with generous padding. (from visual)
- **Audit check**: Are product cards using tiny thumbnails (when imagery is the main decision driver) and multi-column rows split by divider lines? Is the image the dominant element in visually-driven categories (food, travel, fashion, real estate)?
- **Restyle fix**: Convert to a single-column card: large image on top, then title, description, price, CTA; remove divider lines and rely on spacing.
- **Severity**: medium ; **Tags**: layout, cards, imagery, hierarchy

### B-20 Know what matters most to the user and make that element visually dominant  (p.30–31)
- **Rule**: Understand what's important to the user in the context (for restaurants: appealing imagery) and let layout prominence follow that, instead of giving prominence to e.g. the name.
- **Why**: Layout should reflect user priorities; image drives the decision in food contexts.
- **Do / Don't**: Same as B-19 (bad version gives prominence to the title; good version gives it to the image).
- **Audit check**: What is the largest/most prominent element on the card? Does it match the main decision driver for this domain?
- **Restyle fix**: Enlarge the decision-driving content (image) and demote secondary text.
- **Severity**: medium ; **Tags**: hierarchy, layout, imagery

### B-21 Order elements in the sequence the user processes them: image → name → description → price → CTA  (p.32)
- **Rule**: With identical elements (same size and colour, large image), arrangement still matters. Good order: picture at top, then name, brief description, price, then the "Order now" button.
- **Why**: Order makes a noticeable difference to how the card reads; the CTA comes after the user has seen what the product is, what it is, and what it costs. (rationale is partly inferred; PDF only states that arrangement "makes a noticeable difference")
- **Do / Don't**: **Don't**: price at the top (above the image), then picture, name, Order-now button, and description last (below the button). **Do**: picture, name, description, price, Order-now button last.
- **Audit check**: Is the primary CTA last in the card flow, after identifying and price info? Is price floated above the image/title or description placed after the CTA? Flag CTA before descriptive content.
- **Restyle fix**: Reorder DOM/layout: media → title → description → price → CTA.
- **Severity**: medium ; **Tags**: layout, hierarchy, cards, buttons

### B-22 Turn plain radio-list options into selectable cards  (p.33)
- **Rule**: Replace a bland vertical list of text-only options with selectable cards. Each card can carry labels, colours, even icons or images for context and richness.
- **Why**: Plain lists give limited visual differentiation and aren't memorable; cards add interaction and visual appeal and make info more digestible and the interface more engaging.
- **Do / Don't**: Plan picker. **Don't**: single white box with three radio rows in one line of text each: "Basic - 10 credits (£5/month)", "Economy - 50 credits (£10/month)" [selected], "Pro - 100 credits (£15/month)". **Do**: three side-by-side cards – each with a coloured plan label pill (Basic / Economy / Pro; Economy in green), a radio at top-right, large bold number of credits ("10 credits", "50 credits", "100 credits") and price ("$5 / month", "$10 / month", "$15 / month"). Selected (Economy) card is larger/raised with a green border and filled radio. (from visual)
- **Audit check**: Are 2–5 (inference) plan/option choices rendered as plain text radio rows where each option has structured data (name, quantity, price)? Is the selected state visually obvious?
- **Restyle fix**: Make each option a card with label chip, key figure emphasised (big number), price secondary, a radio/check indicator, and a distinct selected state (border colour + scale/elevation).
- **Severity**: low ; **Tags**: layout, cards, forms, states

### B-23 Design form layout after the final output  (p.34)
- **Rule**: Take cues from how the submitted information will be displayed or used: structure and order the form fields/groups to mirror the final output.
- **Why**: Forms are critical touchpoints that are often dull; aligning them with the final result makes the process more interesting, intuitive and aligned with the user's goals.
- **Do / Don't**: "Final display" shows a classified-listing card: Image on top; "Toyota Rav4 Hybrid" + "$32,034" (Product & Price); description ("A 2023 Toyota RAV4 Hybrid, an eco-friendly, sleek SUV…") with "Posted 1 day ago"; Location row "Manchester, UK" with "View map" link; Tags/Categories chips (Hybrid car, Toyota, SUV). Labels with arrows map each region (Image, Product & Price, Description, Location, Tags/Categories) – i.e. the form should have those sections in that order/shape. The corresponding form is on the next page (outside this range).
- **Audit check**: Does the order and grouping of form fields match how the data will be shown (e.g. image upload first, title+price together, description, location, tags)? Flag forms whose structure is arbitrary relative to the output.
- **Restyle fix**: Reorder/group fields to mirror the final card; place related fields side by side as they appear in the output (e.g. name and price on one row).
- **Severity**: low ; **Tags**: forms, layout, interaction-cost

## Balance and harmony (p.36-37)

### C-02 Keep proportion and scale balanced – no element overpowers the others  (p.36)
- **Rule**: No single element should overpower the others. Every element gets its own space and prominence, but not so much that it becomes a distraction.
- **Why**: Balance and harmony make everything on the page fit together, make the design look good, easier to use, and help people quickly understand what is on screen and how to use it.
- **Do / Don't**: See C-04/C-05 (kiwi card example, p.37). Oversized elements are the "don't".
- **Audit check**: Is any one element (hero image, CTA, heading) disproportionately large relative to the rest of the component so that the eye has no clear second stop? Compare sizes of image, heading, body and button within a card.
- **Restyle fix**: Scale down the dominant element until the heading, body and CTA each remain easy to see without any of them dominating.
- **Severity**: medium ; **Tags**: hierarchy, layout, craft

### C-03 Use colour harmony – don't overuse a single colour  (p.36)
- **Rule**: Overusing one colour makes a design feel monotonous or overwhelming. Use complementary or analogous colours to bring variation and emotional balance.
- **Why**: Variation creates emotional balance; a single colour everywhere is monotonous/overwhelming.
- **Do / Don't**: See C-06 (kiwi example).
- **Audit check**: Is one hue used for image background, CTA and small accents all at once? Is the palette limited to a single hue with no complementary/analogous partner?
- **Restyle fix**: Reserve the strong accent for the primary action; use a softer/neutral or analogous/complementary tint for backgrounds and decorative elements.
- **Severity**: medium ; **Tags**: color, hierarchy

### C-04 Keep consistent spacing, typography and element sizes between components  (p.36)
- **Rule**: Maintain consistent spacing, typography and element sizes to create a harmonious relationship among all UI components ("element relationships").
- **Why**: Consistent relationships make the components feel like one system.
- **Do / Don't**: No dedicated example; the kiwi pair (p.37) shows the refined version with heading, body, rating and button at modest, proportionate sizes.
- **Audit check**: Do similar components use different paddings, font sizes or element heights? Are spacing/type/size values drawn from a shared scale/tokens?
- **Restyle fix**: Normalise spacing, type sizes and element sizes to a shared token scale across components.
- **Severity**: medium ; **Tags**: spacing, typography, craft

### C-05 Don't let the hero image and CTA button hog the card  (p.37)
- **Rule**: Image and button must not be too big compared to the rest of the content. Keep the image eye-catching but not overshadowing; make heading and CTA easy to see but "not too flashy".
- **Why**: When image and button are oversized, they hog attention; the eye doesn't know where to go next and crucial details (heading, description, rating) get lost.
- **Do / Don't**: Don't (from visual): kiwi-ice-cream card with a very large circle image, tiny description and rating text, and a full-card-width tall pill "Get now" button. Do (from visual): the image is smaller, the heading stays about the same size, the description and rating text are larger and more readable (the description grows relative to the heading), the rating row sits under it and the "Get now" button is a small, compact pill (not full width), the card is shorter.
- **Audit check**: Is the CTA full-width/very tall on a content card when it is not a mobile footer bar? Is the hero image taking the dominant share of card area while the description and rating text are tiny (compare description/rating size to the heading and the image)? Does the secondary content get visually lost?
- **Restyle fix**: Reduce image diameter/height, shrink CTA to content-width pill with normal padding, bump the description and rating text size (the heading can stay about the same) so the card reads heading → description → rating → CTA.
- **Severity**: medium ; **Tags**: hierarchy, buttons, imagery, layout

### C-06 Don't paint everything the same colour (single-colour overuse)  (p.37)
- **Rule**: Don't use one colour (e.g. green) for the image background, the CTA and smaller elements simultaneously; distribute colours more evenly.
- **Why**: Overuse of a single colour makes the interface feel monotonous and a bit overwhelming.
- **Do / Don't**: Don't (from visual): saturated green circle behind the image, green decorative bits and a big green CTA. Do (from visual): image sits on a pale peach/cream circle with small pink/green confetti shapes; only the "Get now" button carries the green (lime) accent. Colours more even, not leaning on one hue.
- **Audit check**: Count surfaces/elements sharing the same saturated accent hue within one component; flag if the accent is on both a large background shape and the CTA (and other small items).
- **Restyle fix**: Replace large saturated backgrounds with a light neutral/complementary tint; keep the saturated accent for the CTA only.
- **Severity**: medium ; **Tags**: color, hierarchy

## Consistency (p.38-46)

### C-07 Keep essential UI components consistent across the same and different screens  (p.38)
- **Rule**: Make elements function and look similar throughout the design – on the same screen and across screens. Consistency does not mean everything is identical (e.g. product pictures may have different backgrounds), but essential components – titles, buttons, input fields – must remain consistent.
- **Why**: (1) Ease of use – easier navigation; (2) Builds trust – looks more professional and reliable; (3) Reduces cognitive load – less mental effort; (4) Cohesive aesthetic – unified experience that resonates with users. Users learn the UI faster, improving usability and satisfaction.
- **Do / Don't**: Do vary content imagery (backgrounds of product pictures); don't vary the look/behaviour of titles, buttons, inputs.
- **Audit check**: Do the same component types (title, button, input) have different size, radius, colour, padding or behaviour on different screens/sections? Are there one-off component variants not in the design system?
- **Restyle fix**: Consolidate to a single component style per role (title, button, input) via shared tokens/components; allow variation only in content/imagery.
- **Severity**: high ; **Tags**: craft, interaction-cost, hierarchy

### C-08 Use one corner-radius/shape language for all elements  (p.39)
- **Rule**: Use consistent corner radii across pictures, buttons and other elements; don't mix e.g. rounded pictures with square buttons.
- **Why**: Inconsistent radii confuse users, make the design look off-brand and fail to create a cohesive look. A consistent rounded appearance makes the UI easier to navigate and more pleasing (p.40 continuation).
- **Do / Don't**: Don't (from visual, three animal cards): lion picture is a circle but its "Book now" button is a square-cornered black rectangle; the hippo picture is a square image; the third card's avatars are square-ish and the middle card edge is square-cornered; others are rounded. Do (from visual): all three cards have circular images, pill-shaped black "Book now" buttons, rounded card corners and rounded avatars.
- **Audit check**: Collect all `border-radius` values (rounded-*, radius tokens) in a view; flag if sibling cards/buttons/images mix sharp (0) with rounded values or have more radii than the token scale (e.g. a button radius 0 next to rounded-full buttons).
- **Restyle fix**: Define radius tokens (e.g. card radius, button radius, media radius) and apply the same shape family (all rounded or all sharp) to cards, buttons, images, avatars.
- **Severity**: medium ; **Tags**: borders, craft, buttons, cards

### C-09 Use one button colour scheme (primary/secondary/tertiary) everywhere  (p.40-41)
- **Rule**: Don't use many different colours for primary, secondary and tertiary buttons (e.g. tinted to match each card's image). Use one colour scheme for all buttons: black (dark) for main actions and light grey for secondary ones.
- **Why**: Different button colours make users wonder whether each button has a unique function, divert attention from main content and can feel off-brand. One scheme looks organised/professional and makes it obvious what each button does.
- **Do / Don't**: Don't (from visual): each of the three cards has its own button pair coloured to match the illustration (orange for lion, brown for hippo, purple for elephant; light tint "Learn more" + solid "Book now"). Do (from visual): all three cards use the same pair – light grey "Learn more" and near-black/dark brown "Book now".
- **Audit check**: Do equivalent buttons (same role) have different background colours across sibling cards/sections? Count distinct primary-button fills per screen (should be 1).
- **Restyle fix**: Define one primary and one secondary button style (dark fill / light-grey fill) and apply to every card regardless of illustration colour.
- **Severity**: high ; **Tags**: buttons, color, craft, hierarchy

### C-10 Normalise image shapes and sizes by placing them in a consistent container (e.g. circle)  (p.41-42)
- **Rule**: When images vary in shape and size, put them inside a consistent shape such as a circle, then adjust their size/positioning so they are the same size and in similar positions.
- **Why**: Varied shapes/sizes look out of place and disconnected with no unity or flow; the circle gives a cleaner, more put-together look.
- **Do / Don't**: Don't (from visual): three gift-box illustrations of different widths/heights floating on white, at slightly different vertical positions. Do (from visual): each gift box sits in a same-size circle with a soft tint (pale blue, pale pink, pale yellow), centred at the same spot above the title.
- **Audit check**: Do images/illustrations in a row of cards have different dimensions, aspect ratios or alignment? Is there a shared fixed-size mask/container (same width/height/radius)?
- **Restyle fix**: Wrap each image in a fixed-size circular (or other uniform) container with a subtle tint and centre the image; keep the same offset from the card top.
- **Severity**: medium ; **Tags**: imagery, cards, alignment, craft

### C-11 Make cards in a set (3+) the same height  (p.43)
- **Rule**: In a layout with three or more cards, all cards must have the same height.
- **Why**: Looks good and makes things easier and more straightforward for the user.
- **Do / Don't**: Don't (from visual): three accommodation cards (Forest Bungalows, Trailer Homes, Mountain Lodges in the Snowy Region of Scotland) of three different heights because the text lengths differ (short, shortest, longest) – ragged bottom edges and buttons at different y positions. Do: see C-12/C-13 (equal-height cards).
- **Audit check**: In a card grid/row of 3+, compare rendered heights and CTA y-offsets; flag if not equal (code: missing `align-items: stretch`/`h-full`/grid equal rows).
- **Restyle fix**: Use grid/flex stretch so cards share the tallest card's height (or fixed heights) and see C-13 for bottom-aligned CTAs.
- **Severity**: medium ; **Tags**: cards, layout, alignment

### C-12 Keep headings and descriptions about the same length across cards  (p.43-44)
- **Rule**: Make headings and descriptions about the same length so cards naturally share the same height; if you can influence UX copy, keep the same number of lines across all cards.
- **Why**: Keeps cards the same height and makes the design look more balanced.
- **Do / Don't**: Don't (p.43): card 3 title wraps to two lines ("Mountain Lodges in the Snowy Region of Scotland") with a long ~7-line paragraph, while the other titles are 1 line and their descriptions are 4 lines (Forest Bungalows) and 2 lines (Trailer Homes). Do (from visual p.44): titles shortened to "Forest Bungalows", "Trailer Homes", "Mountain Lodges"; each description is ~2 lines ("Surround yourself with the calming vibes of the forest in our cozy bungalows." / "Enjoy a nice stay in our comfy trailer homes. All the essentials without the big price tag." / "Stay in luxury among stunning mountains, where rustic charm meets modern comfort."); all cards equal height with buttons aligned.
- **Audit check**: Compare line counts of titles/descriptions among sibling cards; flag if they differ (e.g. more than a line difference (inference)) or text is much longer in one card.
- **Restyle fix**: Edit/trim copy so each title and description has the same line count (shorten the outlier); otherwise use C-13.
- **Severity**: low ; **Tags**: copy, cards, layout

### C-13 When copy length varies, equalise card height and pin CTAs to the bottom  (p.44)
- **Rule**: If you can't control UX copy and content varies, make all cards the same height but align the CTA buttons at the bottom of each card, leaving any extra space in the middle (between text and button).
- **Why**: Creates the illusion of uniformity even when content length varies.
- **Do / Don't**: Do (from visual p.44 bottom): three cards with different text lengths (Mountain Lodges long, Forest Bungalows medium, Trailer Homes medium), equal height, "Explore offers" buttons all on the same baseline at the bottom with empty space above the button in cards with shorter text. Don't: buttons directly under variable-length text at different heights (p.43 bad example).
- **Audit check**: In equal-height cards, are CTAs at identical y positions? (Code: card is flex column and CTA wrapper has `margin-top:auto`/`mt-auto`.) Flag CTAs that float at different heights.
- **Restyle fix**: Make the card `display:flex; flex-direction:column; height:100%` and push the button container with `margin-top:auto`.
- **Severity**: medium ; **Tags**: cards, alignment, buttons, layout

### C-14 Use a single icon style (outline vs filled, weight, detail, size) within a screen  (p.45)
- **Rule**: Don't mix icons of different sizes or types – e.g. one simple and another highly detailed, or some outlined and others filled on the same screen. Decide on an icon style ahead of time and use it across all UI screens (e.g. outlined everywhere).
- **Why**: Inconsistent icons are a common error that breaks cohesion.
- **Do / Don't**: Don't (from visual, "Account features" list): Manage account icon is a detailed double-person outline, search is a different outline, heart is filled, share is filled, notification bell is filled – mixed outline/filled and different detail levels, and icons slightly different sizes. Do (from visual): all five icons (user, search, heart, share, bell) are consistent thin outline icons of the same size and stroke, in the same purple colour.
- **Audit check**: Within a screen, do icons mix stroke and fill variants, different stroke widths, different sizes or different libraries? (Code: multiple icon packages imported, mix of `fill`/`stroke` styles, inconsistent width/height.)
- **Restyle fix**: Replace all icons with one set in a single style (e.g. outlined), same stroke width and the same size (grid).
- **Severity**: medium ; **Tags**: icons, craft

### C-15 Mix icon styles only to signal state (e.g. filled = selected tab)  (p.45-46)
- **Rule**: Exception: mixing icon styles is OK when it indicates different states. In bottom navigation, the selected tab uses a filled icon while the other tabs use outlined icons.
- **Why**: This subtle style change serves a functional purpose – helping users quickly identify their current location in the app.
- **Do / Don't**: Do (from visual p.46): dark bottom nav bar with four icons; the active "home" icon is filled, on a lilac circular highlight raised/notched in the bar; the other three (clock, pie chart, user) are outlined and grey; annotated "Icon: filled" and "Icon: outlined".
- **Audit check**: If a nav bar uses filled vs outline icons, does the difference map to selected/unselected state rather than arbitrary variation? Is the active tab differentiated (filled)?
- **Restyle fix**: In tab bars/nav, use outlined for inactive and the filled variant of the same icon for the active tab (optionally plus highlight).
- **Severity**: low ; **Tags**: icons, navigation, states

### C-16 Use one icon set (custom or open-source) that fits the brand  (p.46)
- **Rule**: A custom icon set is one way to achieve consistency, but open-source icons are fine if the set aligns with the overall brand image and you don't mix two different sets with varying properties.
- **Why**: Keeps a consistent look.
- **Do / Don't**: Do: one coherent set (custom or open-source) matching the brand. Don't: mix two different icon sets with different properties (weight, style, corner shape).
- **Audit check**: How many icon libraries are in the project/Figma file? Do icons across screens have different stroke weights, terminal shapes or corner styles?
- **Restyle fix**: Pick one library (e.g. a single open-source family matching brand tone) and swap out all others.
- **Severity**: low ; **Tags**: icons, craft

## Bonus tips: whitespace around forms (p.130-131)

### H-05 Don't stretch forms and CTAs to fill wide screens  (p.130)
- **Rule**: On large displays (e.g. MacBook Pro, desktop monitors 1440px wide or more), don't stretch a sign-up form or checkout flow to fill the screen. Don't make inputs and CTAs span almost the full width.
- **Why**: Over-stretched fields overwhelm users and make the interface look cluttered. Long lines of text or fields are hard to read and reduce comprehension.
- **Do / Don't**: Bad (thumbs-down, from visual): "Carbana" page with top nav (logo, Home, About, Pricing, Blog, Contact, Sign up button). The form headline, email, username and password inputs, terms checkbox and the pale blue Sign up button all run edge to edge across nearly the whole 1440-wide page, directly on a flat light-grey background with no container.
- **Audit check**: Is a form input or button wider than roughly a single comfortable column? In code, look for `width:100%` inputs or buttons with no `max-width` on a desktop viewport of 1440px or more, or form fields spanning most of the viewport. (The PDF gives no px max; in the good example in H-06 the card is about 46% of the mockup frame width, from visual – measured on the rendered page image, not a design-px value.)
- **Restyle fix**: Put the form in a narrow centered column or card (add `max-width` and `margin: auto`), and let inputs and buttons fill that container only.
- **Severity**: medium ; **Tags**: [layout, forms, spacing, typography]

### H-06 Contain forms in a defined card and treat white space as a design element  (p.131)
- **Rule**: Give input fields and buttons only the space they need. Concentrate the sign-up or checkout fields in a clearly defined box with ample white space around it. Optionally use a different background colour or a subtle image for the surrounding area.
- **Why**: Cleaner, more focused experience. White space isn't "wasted": it separates sections and draws attention to what matters most. "White space is your friend."
- **Do / Don't**: Good (thumbs-up, from visual): same Carbana page, but the form sits in a narrow centered white rounded card with a soft shadow, on the light-grey page background. The card is about 46% of the mockup frame width (from visual, measured on the render – not a design-px value), with large empty margins on both sides. Inputs have a grey fill and the Sign up button is full width within the card only.
- **Audit check**: Is the primary form or checkout content inside a bounded container (card with background, radius or shadow) distinct from the page background? Is the horizontal margin around it generous?
- **Restyle fix**: Wrap the form in a card (white fill, radius, soft shadow) centered on a tinted background or subtle image, and leave generous side whitespace.
- **Severity**: medium ; **Tags**: [layout, spacing, cards, forms, depth]
