# Known tensions between rules and how to resolve them

> Hand-written file — NOT generated. `scripts/build-knowledge.mjs` does not touch it; edit it here. Only cite rule IDs that exist in `rules.json` (check with `grep '"id": "W2-77"' rules.json`).

Use this table in two places: during **audit** (a finding that follows rule A may be contradicted by rule B; resolve before reporting) and during **restyle** (before applying a batch of fixes, check every planned fix pair against this table and against each other, because a fix for one rule can recreate a violation of another). Resolutions labelled *(general practice)* or *(inference)* are not stated by the playbook; the playbook wins over web (W-) rules. Already consistent, no tension: W3-11 with W1-94 (keep Next/Submit enabled, validate on click), W3-26 with W1-77 (lift a card with translateY and shadow; scale only an image inside it), E-27 with A-24 (E-27 centres the text block; its lines stay left-aligned) and E-19 with E-21 (one family is the recommendation, two split by role are allowed).

## Restatements: count once

These rules check the same thing with the same fix. Report one finding: cite the canonical ID first and add the restatement after it (`rule: F-09 (p.93), also W1-12`), score it once, in the canonical rule's dimension, and keep any detail only the restatement adds. Playbook repeats of the same check (the p.96-97 typography checklist, second worked examples, bad/good pairs on one page, and the p.22 contrast examples that later chapters restate) are already folded into the rule they repeat; their old IDs resolve with `rule.mjs` (F-13 → E-31, F-14 → A-12, F-15 → E-33, F-16 → F-08, F-18 → E-19, F-10 → A-24, G-13 → E-29, D-07 → D-06, C-01 → B-23, C-06 → C-03, B-17 → B-15, B-05 → E-33, B-06 → F-04, B-08 → D-03, B-12 → B-10, A-22 → A-21, C-05 → C-02, C-16 → C-14, E-20 → E-19, E-32 → E-31, E-26 → E-22, F-23 → F-20, F-34 → F-24, G-03 → G-02, G-04 → G-06, H-10 → H-09, H-11 → H-12).
