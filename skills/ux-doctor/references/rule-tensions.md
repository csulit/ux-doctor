# Known tensions between rules and how to resolve them

> Hand-written file — NOT generated. `scripts/build-knowledge.mjs` does not touch it; edit it here. Only cite rule IDs that exist in `rules.json` (check with `grep '"id": "W2-77"' rules.json`).

Use this table in two places: during **audit** (a finding that follows rule A may be contradicted by rule B; resolve before reporting) and during **restyle** (before applying a batch of fixes, check every planned fix pair against this table and against each other, because a fix for one rule can recreate a violation of another). Resolutions labelled *(general practice)* or *(inference)* are not stated by the playbook; the playbook wins over web (W-) rules. Already consistent, no tension: W3-11 with W1-94 (keep Next/Submit enabled, validate on click) and W3-26 with W1-77 (lift a card with translateY and shadow; scale only an image inside it).

| IDs | Tension | Resolution |
|---|---|---|
| F-06 vs A-09 / A-12 / A-05 / F-04 | Raising body text to 16px (F-06) can erase the size or colour step between a title and its muted subtitle, between a name and its meta line (A-09), or between adjacent text styles that differed only by that value. After changing a size/colour token, re-check every pair that differed only by it. | Keep the playbook minimum for body text, then restore the hierarchy with weight, colour or a larger step on the heading instead of shrinking the body again (F-04, A-05). |
| Fix "show the address next to a mailto CTA" (general practice; filed in one audit under F-20 "Minimise interaction cost" and A-20 "Don't mislead", which do not themselves prescribe it) vs A-07 / W1-82 / W3-17 | An "Or email …" line next to a mailto button gives a second route to the same destination and can read as a third control. Keep one filled primary. | Show the address as plain text only if no second same-destination button is in the viewport; otherwise keep the button and put the address in the footer or contact section. |
| W2-08 vs B-15 / B-17 | Golden-ratio spacing (W2-08) conflicts with base-unit multiples (B-15, B-17). The playbook wins. | Use the project's base-unit scale (e.g. 4/8) and record W2-08 as not applied (web rule). |
| W1-92 vs G-12 | W1-92 says never place the destructive button where confirm normally sits; G-12 puts Cancel on the left and the destructive action on the right. The playbook wins. | Follow G-12 for the order; keep W1-92's other half (red only for destruction, destructive visually distinct from the affirmative path). |
| W3-14 vs A-16 | W3-14 suggests about 12px within groups and about 40px between sections; A-16 uses about 12px label-to-field and about 32px between fields. The playbook wins. | Use A-16's 12/32 for forms and W3-14's ratio principle (tighter within than between) elsewhere; flag only equal gaps. |
| W3-25 vs D-05 | W3-25 stacks a tight darker shadow with a soft one; D-05 says no harsh/tight dark shadows. The playbook wins. | Use soft, diffuse shadows (D-05); W3-25's hairline border is acceptable on dark backgrounds as a web addition (inference). |
| W3-30 vs F-06 | W3-30 uses 13px text and 32px rows for compact UIs, which sits below F-06's 16px body. Applies to dense tool UIs only. | Use 13px only in dense data/tool UIs, never below the 12px floor (F-06); marketing and reading text stays at the playbook size. |
| W2-77 vs W3-17 / W3-19 / A-05 | W2-77 wants the identical CTA at top and bottom of the page; W3-17/W3-19 and A-05 allow one primary/emphasis per view. | A repeat at the closing section is fine; two copies of the same CTA inside one viewport (sticky header + hero) are not. See the same-destination test in ux-hierarchy-clarity. |
| One-weight brand font vs E-33 / B-05 | A brand that uses a single weight cannot follow "heavier headings, lighter body". | Record it under **Accepted by design** (excluded from scoring) but do not claim hierarchy by weight; hierarchy must then come from size, colour and spacing (F-04, A-05). |
| Sticky top header on mobile vs H-09 | H-09 says the top of the screen is hard to reach by thumb; a tall sticky top header also eats viewport height and holds controls in that zone. | Keep the sticky header compact (or hide it on scroll down, show on scroll up) and keep primary actions in the thumb zone (bottom bar or bottom-anchored CTA, H-09) *(general practice for the compact/hide part)*. |
| Sticky/fixed header vs anchor offsets and z-index (general practice; W3-32) | A sticky header hides in-page anchor targets and can sit above or below the skip link, menus and modals. | Add `scroll-padding-top`/`scroll-margin-top` at least the header height, order z-index through stacking contexts (W3-32), and re-check the header CTA against the hero CTA (W3-17). |
| E-17 / F-17 / C-08 vs W5-02 / W5-12 (AI-look tells) | The playbook recommends Inter and one corner-radius language for all elements; generic-UI sources list "Inter everywhere" and "one radius on everything" among the tells. The playbook wins. | Inter, a single radius language and an unchanged-but-passing framework theme are never findings on their own; count a palette or type default as one W5-01 tell only when nothing in the brief or tokens chose it, and keep radii consistent while scaling them with surface size (W1-11). |
| W1-79 vs W5-08 | W1-79 adds an accent edge on hover to clickable cards; W5-08 flags a static coloured left/top stripe on cards. | A hover-only edge cue on clickable cards is fine; a permanent stripe on every card is the tell. Status alerts whose edge colour encodes severity are exempt. |
| W1-82 vs W5-07 | W1-82 turns the hero secondary into a text link with an arrow; W5-07 flags arrows appended to every link and button. | Keep the arrow on that one text link (and on links that leave the flow); remove arrows from the other controls. |
| W2-03 vs W5-03 | W2-03 cascades list and card entrances; W5-03 says not to fade-and-slide every section on scroll. | Cascade items that arrive in response to the user or data loading (W2-03); drop scroll-triggered entrances on page sections, keep at most one page-level moment, and never start content hidden (W5-04). |
| D-16 / D-18 / E-01 vs AI-look glass | Generic-UI sources list indiscriminate glass panels as a tell; the playbook allows glass that fits the brand and keeps text legible. The playbook wins. | Judge glass by D-16/D-18/E-01 (legibility, background, purpose); it is not a W5-01 tell by itself. |
| G-14 / G-16 vs W5-10 | The playbook adds icons (checkmarks, stars, colour-coded icons) to break up product copy; W5-10 flags emoji bullets and a generic icon tile on every feature card. | Icons that name a real object or status stay (G-14); replace emoji bullets and adjective icon tiles (bolt = fast, shield = secure) with the project's icon set, product imagery (W1-84) or nothing. |
| A-11 vs W5-14 | A-11 makes the value the most prominent text in metric cards; W5-14 flags unsourced stat-banner rows. | Keep A-11's hierarchy for real, sourced metrics; remove or merge decorative stat rows rather than restyling them. |
| W2-06 vs W5-09 | W2-06 wraps related elements in a shared container; W5-09 flags cards nested in cards. | One container level per group is fine (W2-06); a bordered or shadowed container inside another is the tell. Flatten the inner one with spacing and a heading. |
