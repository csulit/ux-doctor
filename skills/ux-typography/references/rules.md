## Typography (p.72-84)

### E-13 Choose a serif typeface for formal sectors (law, accounting, education)  (p.72)
- **Rule**: Pick a font like an outfit: appropriate, comfortable, effective for the message. In formal sectors (law, accounting, education) use a serif typeface for a classic, polished tone.
- **Why**: Typeface conveys tone for the sector.
- **Do / Don't**: Example "Faircase – Fair and Square." law-firm landing page: serif logo, nav, large serif headline, serif body and stats ("1542 Cases / 53 Lawyers / 726 Connections"), dark red/maroon CTA, tan background panel with portrait photo (from visual).
- **Audit check**: Does the typeface personality match the sector/brand (formal sector with playful/techy font = mismatch)?
- **Restyle fix**: Swap to a classic serif (e.g. Merriweather-like, from visual) for headings/body in formal contexts.
- **Severity**: low ; **Tags**: typography, craft

### E-14 Consider a script/handwritten typeface for relaxed, personal sectors like beauty  (p.72-73)
- **Rule**: For beauty and similar relaxed, inviting sectors, a script typeface can be experimented with to feel warm and personalised.
- **Why**: Warm, personalised mood.
- **Do / Don't**: Example "EVELIA" skincare: light handwriting-style headline "Essential skincare collection / UP TO 70% OFF", spaced small-caps sans nav, cream background, product photos (from visual). Script is used for headline only; small text stays plain sans (from visual).
- **Audit check**: If a script font is used, is it restricted to display/headline text and still legible? Is it appropriate for the sector?
- **Restyle fix**: Use script for the hero headline only; keep body/UI text in a simple readable font.
- **Severity**: low ; **Tags**: typography, craft

### E-15 Use sans-serif for tech, music-streaming, messaging apps  (p.73)
- **Rule**: In tech, music streaming and messaging contexts, sans-serif fonts are the go-to for a sleek modern aesthetic.
- **Why**: Resonates with those industries.
- **Do / Don't**: Example "Tucard" dark landing page: geometric sans headline "Simplify All Transactions in One Card" (with "One Card" in magenta), sans nav, small body, stats "42K+ / 12K+", glass-like cards (from visual).
- **Audit check**: Does a tech/app product use a decorative or serif face where sans is expected?
- **Restyle fix**: Switch to a clean sans-serif (Inter/Manrope-like).
- **Severity**: low ; **Tags**: typography, craft

### E-16 Pick a font that is both readable and aesthetically pleasing  (p.74)
- **Rule**: Font selection is about clarity and readability as well as beauty: choose a font that is easy to read, looks good and matches the intended vibe. Avoid decorative/novelty faces for titles, body and buttons.
- **Why**: A poorly chosen font becomes the "Achilles heel" – message hard to get across, users frustrated.
- **Do / Don't**: Don't: article card with blackletter/gothic-style headline and condensed quirky body and button font (from visual) – hard to read. Do: same card with clean serif headline ("The Art of Achieving Success: Unveiling the Secret Ingredients to a Fulfilling Life"), plain sans body and "Learn more" button.
- **Audit check**: Any display/decorative/blackletter/condensed font used for body text, buttons or UI labels? Is x-height/legibility ok at body size?
- **Restyle fix**: Replace with a neutral legible text typeface; keep decorative faces (if at all) for a logo.
- **Severity**: high ; **Tags**: typography, accessibility

### E-17 Prefer proven, versatile UI fonts  (p.75)
- **Rule**: Reliable "good in any situation" fonts that balance style with readability: Inter, Gotham, Lato, Open Sans, San Francisco, Helvetica, Manrope, Roboto.
- **Why**: They are trusted, readable all-rounders.
- **Do / Don't**: List only.
- **Audit check**: Is the primary font among well-tested UI typefaces (or equivalent quality)?
- **Restyle fix**: Default to one of these list fonts when no brand font exists.
- **Severity**: low ; **Tags**: typography

### E-18 Only use properly licensed fonts (Google Fonts for free)  (p.75)
- **Rule**: Make sure the font can be used for personal or commercial purposes as your project requires; never use fonts without proper license. Google Fonts is a reliable source of free, safe fonts.
- **Why**: Legal/licensing safety.
- **Do / Don't**: Text only.
- **Audit check**: Are fonts self-hosted/loaded from a licensed source (Google Fonts, purchased licence)? Flag unlicensed commercial fonts (e.g. ripped webfonts).
- **Restyle fix**: Replace with an open-licensed (Google Fonts) alternative.
- **Severity**: medium ; **Tags**: typography, craft

### E-19 Use at most 2 different fonts per UI  (p.75-76)
- **Rule**: Never use more than two font families. More than two looks cluttered, confusing and off-brand.
- **Why**: Messy and harder to look at; one or two fonts feel clean.
- **Do / Don't**: Don't: music app screen with four families – Poppins (title) + Open Sans (subtitle), Times (track titles), Telex (button, UPPERCASE "DISCOVER MORE"). Do: same screen all Inter ("Music", "Special edition", track titles, "Discover more").
- **Audit check**: Count distinct `font-family` values (excluding icon/mono fallbacks) in CSS/Figma text styles: > 2 → flag.
- **Restyle fix**: Consolidate to 1 (ideally) or 2 families; remap all text styles.
- **Severity**: high ; **Tags**: typography, craft, hierarchy

### E-20 Best practice: one versatile font, vary weight and size for dynamics  (p.76)
- **Rule**: For a clean, professional look, stick to one versatile font and create dynamics via different weights and sizes.
- **Why**: Cleaner and more professional.
- **Do / Don't**: Do: all-Inter example (see E-19).
- **Audit check**: Is hierarchy built with weight/size in a single family rather than extra families?
- **Restyle fix**: Replace secondary family with a different weight/size of the primary family.
- **Severity**: medium ; **Tags**: typography, hierarchy

### E-21 If using two fonts: one for headings, one for body, from proven pairings  (p.76)
- **Rule**: Experienced designers can use two fonts: one for headings, another for paragraphs. Pairs named: Playfair Display (headings) + Sources Sans Pro (body); Raleway + Merriweather; Montserrat + Open Sans. Figma's curated pairing list: www.figma.com/google-fonts.
- **Why**: A classic combo that adds range without clutter.
- **Do / Don't**: Text only.
- **Audit check**: If two families exist, is the split by role (heading vs body) and are they a deliberate contrasting pair?
- **Restyle fix**: Assign one family to headings, the other to body; use a pair from the list.
- **Severity**: low ; **Tags**: typography

### E-22 Keep body-copy line length at 45-75 characters on desktop  (p.76-77)
- **Rule**: For body copy on desktop, line length should be 45-75 characters per line (research-backed sweet spot). These are guidelines, not strict rules.
- **Why**: Optimises readability/visual appeal; keeps focus and prevents users feeling overwhelmed or losing their place.
- **Do / Don't**: Diagram with ruler markers 0, 20, 45, 75, 100 characters in a browser frame. Green (good) text blocks: one spanning to ~75, another ending at roughly 45 (from visual). Pink (bad) blocks: a narrow block of ~20 characters per line (too short, choppy) and a wide block running out to ~100 characters (too long).
- **Audit check**: Measure real characters per line of the rendered body paragraph (browser: `Range.getClientRects()` per line plus the line's text length; or font metrics) – do not infer it from a `ch` value: 1ch is the width of the `0` glyph, not an average character (one proportional UI font measured 72ch ≈ 93 real characters per line, while 36em ≈ 73.5; inference from a real-project measurement). Flag if >75 or <45 on desktop (e.g. no `max-width` on a paragraph in a wide container, `max-w-none`, full-width text).
- **Restyle fix**: Cap the column in `em`/`rem`; rule of thumb for proportional UI fonts about 30–36em gives 45–75 characters (inference – 36em ≈ 73.5 characters in one measured font, about 2.0 characters/em; verify per font by re-measuring). Use `ch` only for monospace fonts. Centre or left-align the constrained column; `max-w-prose` (65ch) is not a safe shortcut for proportional fonts.
- **Severity**: high ; **Tags**: typography, layout, accessibility

### E-23 On mobile aim for 30-40 characters per line  (p.77)
- **Rule**: On mobile, the rule of thumb is 30 to 40 characters per line.
- **Why**: Smaller screens; keeps text easily digestible without hurting readability.
- **Do / Don't**: Text only.
- **Audit check**: At mobile widths, count real characters per line of body copy (measure rendered lines, not `ch`): outside ~30-40 (guideline) → check.
- **Restyle fix**: Adjust horizontal padding / font-size so mobile lines land at 30-40 chars.
- **Severity**: medium ; **Tags**: typography, mobile

### E-24 Measure line length with tools instead of counting  (p.77)
- **Rule**: Use Figma plugins like "Character counter" or online tools to check characters per line.
- **Why**: Avoid manual counting.
- **Do / Don't**: Text only.
- **Audit check**: Tooling note – measure via plugin/JS: per-line `Range.getClientRects()` with the text of each line, or font metrics; a width ÷ "average character width" guess or a `ch` conversion is not a measurement (1ch = width of `0`).
- **Restyle fix**: n/a (process tip).
- **Severity**: low ; **Tags**: typography, craft

### E-25 Allow flexibility in line length by content, layout and device  (p.77)
- **Rule**: 45-75 chars is not one-size-fits-all; depending on content, layout, or target device some flexibility is beneficial.
- **Why**: Context changes ideal measure.
- **Do / Don't**: Text only.
- **Audit check**: Deviations from 45-75 should be justified (e.g. mobile 30-40, short UI captions).
- **Restyle fix**: Tune per breakpoint.
- **Severity**: low ; **Tags**: typography, layout

### E-26 Don't let body text span the full page width  (p.78)
- **Rule**: Text stretching across the whole page width is hard to read; constrain it.
- **Why**: Eyes must travel a long distance from end of one line to start of next, increasing eye strain and reducing readability.
- **Do / Don't**: Don't: dog-community landing page – below the hero, heading "Why people love dogs" and a paragraph running the full container width (~100+ characters per line, 4 lines), small grey text (from visual).
- **Audit check**: Paragraph container whose rendered lines exceed ~75 real characters (measure per line in the browser, see E-22; do not convert from `ch`, since 1ch is the width of `0`, not an average character) with long unbroken lines.
- **Restyle fix**: Add a `max-width` that yields ≤ 75 real characters per line; for proportional UI fonts about 30–36em is a starting point (inference – verify per font).
- **Severity**: high ; **Tags**: typography, layout

### E-27 Narrow centered text column (≤75 chars) is a valid fix  (p.79)
- **Rule**: Center-align the text *block* below the image/intro and limit line length to max 75 characters.
- **Why**: Eyes travel less, easier to move from line end to next line start.
- **Do / Don't**: Do: paragraph block ("Why people love dogs", 4 lines at ~70 chars) is a narrower column positioned in the centre of the container; the heading is left-aligned with the paragraph inside the column (from visual – the block is centred, text itself remains left-aligned).
- **Audit check**: Text block in wide container is constrained to ≤75 real characters per line (measure it, see E-22) and centred (`mx-auto max-w-…`).
- **Restyle fix**: Wrap in centred container with max-width ≈75 characters.
- **Severity**: medium ; **Tags**: typography, layout, alignment

### E-28 Narrow left-aligned text column (≤75 chars) is the other valid fix  (p.80)
- **Rule**: Left-align the text with line length not exceeding 75 characters for a traditional, straightforward feel.
- **Why**: Restricted line length makes text easily digestible, reduces eye strain.
- **Do / Don't**: Do: paragraph (6 lines) left-aligned with the page's hero text left edge, block ends well before the right side of the container (from visual), leaving empty space at right.
- **Audit check**: Left-aligned body text with measure ≤75 characters, aligned to the same left edge as the heading/hero content.
- **Restyle fix**: Set a max-width that gives ≤75 real characters per line (about 30–36em for proportional UI fonts, inference – verify per font; `ch` only for monospace), keep left alignment with the hero's left edge.
- **Severity**: medium ; **Tags**: typography, layout, alignment

### E-29 Break long paragraphs into shorter chunks  (p.81)
- **Rule**: In content-heavy sections use shorter paragraphs; split long blocks into bite-sized chunks with visible space between them.
- **Why**: Long blocks overwhelm users, hard to absorb and stay engaged; breaks make content easier to scan/digest, give natural stopping points, highlight crucial info, make reading more interactive.
- **Do / Don't**: Don't: "GreenMeal" card with one dense ~9-line paragraph block. Do: same text split into three short paragraphs (~3-4 lines each) with a blank gap (paragraph spacing) between them.
- **Audit check**: Paragraphs longer than ~5-6 lines (≈ 80-100 words – inferred) without breaks; no margin between paragraphs.
- **Restyle fix**: Split at sentence/idea boundaries; add paragraph spacing (e.g. ~0.75-1em, inferred).
- **Severity**: medium ; **Tags**: typography, layout, spacing

### E-30 Add subheadings (with icons/lines/space) to shorter paragraphs  (p.82)
- **Rule**: Give each short paragraph a subheading – a roadmap to the content. Make sections stand out further with icons, lines (dividers) or extra space.
- **Why**: Subheadings make text scannable, grab attention, preview the paragraph, and break information into digestible parts.
- **Do / Don't**: Don't: card titled "GreenMeal" with one dense paragraph. Do: card titled "GreenMeal: your healthy dining partner" containing three sections, each with an emoji-icon + bold subheading ("Organic ingredients for optimal nutrition", "Unlock a world of culinary delights", "Customize to fit your lifestyle") followed by a short paragraph, thin divider lines between sections and extra spacing; the main title is bigger/bolder than subheadings, which are bolder than body (from visual).
- **Audit check**: Text sections > 1 paragraph or long copy without subheads; subheads present but not visually distinct (same size/weight as body).
- **Restyle fix**: Add descriptive subheadings (semibold, slightly larger than body), optional icons, dividers (1px light line) and increased spacing between sections.
- **Severity**: medium ; **Tags**: typography, hierarchy, layout, spacing

### E-31 Avoid pure black (#000000) text on white, and pure white (#FFFFFF) on dark  (p.83)
- **Rule**: Don't use #000000 text on white backgrounds or #FFFFFF text on dark backgrounds. Use off-black/dark grey for headings and a lighter grey for body text.
- **Why**: Pure extremes are hard on the eyes and disrupt visual harmony; a softer scheme is soothing, sophisticated and balanced; dark grey headings say "this is significant" without screaming; lighter grey text stays readable without overwhelming.
- **Do / Don't**: Don't: dark card Heading #FFFFFF / Body #FFFFFF on black; light card Heading #000000 / Body #000000 on white. Do: see E-32.
- **Audit check**: Grep CSS/tokens for `color: #000`, `#000000`, `black`, `#fff`/`#ffffff`/`white` used as text colour on respective extremes (`text-black`, `text-white` on `bg-black`/`bg-white`/very dark).
- **Restyle fix**: Replace with off-black/dark-grey tokens and lighter grey body (E-32 values).
- **Severity**: medium ; **Tags**: contrast, color, typography, dark-mode

### E-32 Use graded greys: darker heading, lighter body text (reference values)  (p.83)
- **Rule**: Heading darker/stronger than body text, both soft. Reference values from the example — Dark mode (on black background): heading #F2F2F2, body #CACACA. Light mode (on white background): heading #1A1A1A, body #4E4E4E.
- **Why**: Refined contrast "that just feels right" while keeping a heading/body hierarchy.
- **Do / Don't**: Do: example "The scoop on ice cream" card in both DARK and LIGHT variants using values above; heading visibly brighter/darker than body. Don't: identical colour for heading and body (#FFFFFF/#FFFFFF, #000000/#000000).
- **Audit check**: Heading and body use different, non-extreme colours; light theme text ≈ #1A1A1A heading / ≈ #4E4E4E body (contrast of #4E4E4E on white = 8.32:1 – computed, still above WCAG AA); dark theme ≈ #F2F2F2 / ≈ #CACACA. Flag body greys lighter than AA 4.5:1 (inference: threshold not on p.83).
- **Restyle fix**: Set text tokens: light — heading #1A1A1A, body #4E4E4E; dark — heading #F2F2F2, body #CACACA.
- **Severity**: medium ; **Tags**: contrast, color, typography, hierarchy, dark-mode

### E-33 Use heavier weights for headings and lighter for body  (p.84)
- **Rule**: Headings: bold, semibold or medium; paragraphs: regular, sometimes light. Don't use the same weight for heading and body.
- **Why**: Weight adds visual interest and tells users what is most important; thin body weights stay readable and don't compete with headings.
- **Do / Don't**: Don't: card "The canine connection" with heading Regular and body Regular – hard to tell what's important. Do: heading Bold, body Regular – clear what to focus on and what to skim.
- **Audit check**: Compare `font-weight` of headings vs body: equal (e.g. 400/400) → flag. Headings should be ≥500 (medium/semibold/bold), body 300-400.
- **Restyle fix**: Set headings to 500-700 and body to 400 (or 300).
- **Severity**: high ; **Tags**: typography, hierarchy

## Typography: exceptions and extremes to avoid (p.85-87)

### F-01 Light-weight headings are acceptable only if clearly larger than body (colour reinforces)  (p.85)
- **Rule**: Modern sites (Pleo, Linear) use light/regular font weights for headings and still get clear hierarchy, because they do not rely on weight alone: headings use a darker colour than paragraphs (paragraphs lighter) and, above all, headings are set noticeably larger than the rest of the text. If you break the "bold headings" convention, size (mostly) + colour must compensate.
- **Why**: Hierarchy comes from combined contrast of size, colour and weight; size contrast is the strongest, so a big heading stays dominant even at light weight.
- **Do / Don't**: Do (Pleo hero screenshot, from visual): large, light-weight dark headline "Your business spending, in safe hands" over smaller, greyer paragraph and a dark pill CTA. Don't: use a light heading weight with heading size ≈ body size and same colour.
- **Audit check**: Is any heading using weight < medium (≤400)? If yes, it is acceptable only when its size is clearly larger than body text (visually unmistakable) – size is what p.85 says these sites rely on MOST. A darker heading colour vs body (lighter paragraphs) is a reinforcement that helps, not a substitute. Light-weight heading that is not clearly larger than body → hierarchy is lost, flag it, even if its colour is darker than body.
- **Restyle fix**: Either raise heading weight to medium/semibold/bold, or keep light weight but increase heading font-size substantially and darken heading colour relative to paragraph colour.
- **Severity**: medium ; **Tags**: hierarchy, typography, color

### F-02 Never use text colour that is too light (light-grey text)  (p.86)
- **Rule**: Don't set text in very light grey in the name of minimalism. Example pair: body text `#A9A9A9` on white = fails WCAG AA and AAA (bad); body text `#626262` on white = passes WCAG AA and AAA (good, per the PDF's badge). **[ux-doctor erratum: #626262 on white computes to 6.1:1 = AA pass only; AAA normal text needs 7:1. Use computed values.]** Keep text dark enough to pass contrast (see F-09).
- **Why**: Light-grey text forces squinting/tilting the screen (e.g. reading on a phone in a coffee shop), hurts users with poorer vision.
- **Do / Don't**: Same card (image of yellow fish, heading + 5-line paragraph). Bad card: paragraph #A9A9A9, badge "WCAG AA: Fail / WCAG AAA: Fail". Good card: paragraph #626262, "WCAG AA: Pass / WCAG AAA: Pass". Heading is near-black in both.
- **Audit check**: Compute contrast of every text colour vs its background; flag body text lighter than ~#767676-equivalent (inference) / below 4.5:1 (the PDF shows #A9A9A9 failing and #626262 passing). Look for Tailwind `text-gray-300/400`, `opacity-50` on text, placeholder-grey used for content.
- **Restyle fix**: Darken paragraph/secondary text to at least ~#626262 on white (or any value giving ≥4.5:1); keep it lighter than headings to preserve hierarchy.
- **Severity**: high ; **Tags**: contrast, accessibility, typography, color

### F-03 Avoid extra-light (thin) font weights for body text  (p.87, reaffirmed p.96)
- **Rule**: Stick to regular or medium weights for the bulk of text. Avoid Extra-light / Thin (e.g. Inter Extra Light, Inter Thin).
- **Why**: Thin strokes blend into the background or break apart, especially on small screens or poor lighting; hurts older adults and visually impaired users.
- **Do / Don't**: Same coral-reef card twice. Bad: paragraph in "Font-weight: Extra-light" (faint, thin). Good: "Font-weight: Regular". Heading is semibold in both.
- **Audit check**: Any body/paragraph `font-weight` < 400 (100/200 especially; Tailwind `font-thin`, `font-extralight`)? Flag. `font-light` (300) on small text is a warning (inference).
- **Restyle fix**: Set body to `font-weight: 400` (or 500 if the font is delicate/small).
- **Severity**: high ; **Tags**: typography, accessibility, contrast

## Typography: size, line-height, contrast, alignment (p.88-94)

### F-04 Use size to signal which text is important  (p.88)
- **Rule**: Size is the most direct way to establish hierarchy; bigger elements attract more attention. Make the message that matters most the largest.
- **Why**: Users read the biggest text first; if the wrong text is biggest they act on the wrong message (analogy: giant "Start the engine and go full speed" vs. small "Wait until you see the green light!" at a red light → crash).
- **Do / Don't**: Two cards with a traffic-light image. Bad: "Wait until you see the green light!" tiny, "Start the engine and go full speed" large. Good: "Wait until you see the green light!" large, "Start the engine and go full speed" small.
- **Audit check**: Is the largest text on each card/section the one the user most needs to see (primary message, warning, key value)? Is a secondary/optional/ancillary text larger than the critical one?
- **Restyle fix**: Re-assign type scale so the most important text gets the largest size and secondary text is reduced.
- **Severity**: high ; **Tags**: hierarchy, typography

### F-05 Make headings clearly bigger than body text  (p.89)
- **Rule**: A heading must be much larger than body text. Even with the same colours and fonts, a bigger heading alone creates clear hierarchy and contrast; a title the same size as regular text makes it hard to tell what is important and doesn't attract attention.
- **Why**: Without size contrast users can't scan for importance and may not be drawn to read on.
- **Do / Don't**: Watch-promo card (serif font, same colours). Good (first card): large two-line heading "Timeless elegance watch edition", small paragraph, small black "Get it today" button. Bad (second card): heading "Timeless elegance watch edition" at the same small size as the paragraph, single line.
- **Audit check**: heading font-size ÷ body font-size ≈ 1? (heading ≈ body size = violation). Compare computed sizes of h1/h2/card titles vs paragraph.
- **Restyle fix**: Increase heading size to a clear step up (compare example p.95: 28px heading vs 18px body ≈ 1.55x; p.90: 32px title vs 16px body = 2x).
- **Severity**: high ; **Tags**: hierarchy, typography

### F-06 Use readable font sizes: 16px for main text, never below ~12px (10px floor)  (p.90, reaffirmed p.96-97)
- **Rule**: The "gold standard" for main/body copy is 16px (sweet spot for most people). Can be tweaked by platform or typeface. Avoid anything below 12px for main text; the "things to avoid" list says no font sizes smaller than 10px (platform-dependent). When in doubt test on different devices and with other people.
- **Why**: Small text is hard to decipher, can make users bounce, and creates accessibility problems for visually impaired users.
- **Do / Don't**: "Sea turtles" card with tabs (All / Life / Early years / Special skills). Bad card: title 32px, tabs 16px, body paragraph 10px (tiny, long text). Good card: title 32px, tabs 16px, body paragraph 16px.
- **Audit check**: Main text `font-size` < 12px = violation (p.90: "anything below 12px for main text should be avoided"). Any text < 10px = violation, but platform-dependent (p.96: "smaller than 10px, though this can depend on the platform"). Body < 16px = check, not automatic fail (inference): p.90 calls 16px the "gold standard" but "not a one-size-fits-all rule". (Tailwind `text-[10px]`; `text-xs` = 12px is at the limit when used for main text.) Check on mobile too.
- **Restyle fix**: Set body copy to 16px (adjust for platform/typeface); raise any 10px content text to ≥12px, preferably 16px.
- **Severity**: high ; **Tags**: typography, accessibility, mobile

### F-07 Use generous line-height for body text: 1.5-1.6x (150-160%)  (p.91)
- **Rule**: For standard ~16px text, line-height should be 1.5-1.6x the font size (150%-160%). Above 2x paragraphs look like they float; below 1.2x text feels cramped.
- **Why**: Comfortable reading without text looking squished or stretched; the same font/size/colour can go from "meh" to "wow" by line-height alone.
- **Do / Don't**: "The magic of coffee" card twice, identical font/size/colour. Bad: tightly packed lines (cramped). Good: more open spacing between lines.
- **Audit check**: Paragraph `line-height` ratio: <1.2 = fail (cramped); 1.2-1.5 = weak (inference); 1.5-1.6 = ideal; >2 = fail (floating). Tailwind `leading-none/tight` on paragraphs = violation.
- **Restyle fix**: Set paragraph `line-height: 1.5`-`1.6` (e.g. `leading-relaxed`/1.6 for 16px).
- **Severity**: high ; **Tags**: typography, spacing

### F-08 Tighter line-height for headings, looser for paragraphs  (p.92, reaffirmed p.96-97)
- **Rule**: Line-height should scale inversely with text size: bigger text → smaller line-height ratio. Headings use tight line-height (example 120%; a 36px heading → about 1.3x / 130%), paragraphs use generous (160%). Never give a heading a bigger line-height than the paragraph.
- **Why**: Tight headings look compact and impactful ("this is important"); open paragraphs are inviting and easier to read; creates balanced visual flow and easier scanning.
- **Do / Don't**: "Unveiling the wonders…" card. Bad: heading Line-height 160% and paragraph Line-height 120% (inverted: airy heading, cramped body). Good: heading 120%, paragraph 160%.
- **Audit check**: Compare the computed heading line-height ratio with the paragraph ratio of the same context. Violation = heading line-height ≥ paragraph line-height (playbook: never bigger), or heading lines visibly colliding/clipped (inference). The heading ratio shrinks as size grows (playbook: 120% in the card example, ~1.3 for a 36px heading), so a fixed "> 1.3" cut-off is not a failure test: large display type (≥ ~56px) at 1.0–1.15 is not a violation by itself (inference), and a 1.3 multi-line heading beside 1.6 body passes.
- **Restyle fix**: Headings `line-height` ≈ 1.2-1.3; paragraphs 1.5-1.6.
- **Severity**: medium ; **Tags**: typography, spacing, hierarchy

### F-09 Ensure text/background contrast of at least 4.5:1 (WCAG AA)  (p.93, reaffirmed p.96-97)
- **Rule**: For most text a contrast ratio ≥ 4.5:1 is accessible; designs should meet at least WCAG Level AA. Don't use faint text on a similarly faint background for trendiness; never use bad contrast solely for an aesthetic look. Tools: WebAIM guides, Coolors.co, Figma "Contrast" plugin by WillowTree.
- **Why**: Trendy low-contrast designs are hard to read for people with vision difficulty or in bad lighting; put readability first.
- **Do / Don't**: "The Pawsome World of Dogs" card with purple/lilac background. Bad: white/light text on lilac → "WCAG AA: Fail, AAA: Fail". Good: dark purple/near-black heading and body text on same lilac background → AA Pass, AAA Pass.
- **Audit check**: Contrast ratio of each text/background pair < 4.5:1 → fail (normal text). Check text over tinted/coloured card backgrounds and over images.
- **Restyle fix**: Darken text (or lighten/darken background) until ≥4.5:1; on mid-tone coloured backgrounds use dark text instead of white.
- **Severity**: high ; **Tags**: contrast, accessibility, color

### F-10 Left-align text; reserve centre/right for special cases  (p.94, reaffirmed p.97)
- **Rule**: Left-aligned text is generally best for readability, especially longer paragraphs, lists and long-form content (consistent starting point per line; matches left-to-right reading). Centre alignment is OK for titles or short text meant to grab attention, and right/centre for decorative or artistic elements.
- **Why**: Consistent line start makes it easier to follow lines; ragged left edges slow reading.
- **Do / Don't**: Dark navy "The Critical Role of Sleep…" card twice. Bad: heading and paragraph centred ("Text alignment: Center"). Good: heading and paragraph left-aligned ("Text alignment: Left").
- **Audit check**: `text-align: center|right` (Tailwind `text-center`/`text-right`) on multi-line paragraphs (>2-3 lines (inference)), lists or long descriptions → violation. Centre on short titles/hero lines OK.
- **Restyle fix**: Set `text-align: left` (`text-left`) on body paragraphs and multi-line copy; keep centre only for short titles.
- **Severity**: medium ; **Tags**: typography, alignment

## Typography: putting it together (p.95)

### F-11 Worked example: bad vs good typography card (full spec)  (p.95)
- **Rule**: Combine all principles on one card. Good card spec: heading line-height 120%, font-size 28px, weight Bold, colour `#1B000D` (near-black with tint); body line-height 160%, font-size 18px, weight Regular, colour `#5E5458` (softer than heading); button label font-size 18px, weight Semibold, colour `#141B12`; left-aligned text; WCAG AA and AAA Pass. Bad card spec: heading line-height 170%, 22px, Medium, `#000000`; body line-height 110%, 18px, Regular, `#000000`; button label 22px, Regular, `#FFFFFF` on pink; centre-aligned; button label WCAG AA Fail / AAA Fail.
- **Why**: Line height, contrast, weight, size and colour differences together make text more readable and engaging ("elevate design from good to great").
- **Do / Don't**: Card with Japan illustration, title "Exploring the land of the rising sun: A journey through Japan's rich culture and history", paragraph, pink "Learn more →" button. Bad: centred text; heading only 22px (barely > 18px body), medium weight, pure black; heading line-height 170% vs body 110% (inverted); pure black body (same as heading); white button label on pink fails contrast. Good: left-aligned; heading 28px bold, tight 120%; body 18px regular grey-brown, loose 160%; heading darker than body; dark semibold button label on pink passes.
- **Audit check**: Test each point: heading/body size gap (28 vs 18 ≈ 1.55x), heading weight > body weight, heading darker than body, heading LH < body LH, pure #000/#FFF not used, button label contrast passes, paragraph left-aligned.
- **Restyle fix**: Apply the good spec: heading 28/120% bold `#1B000D`; body 18/160% regular `#5E5458`; button text semibold dark (`#141B12`) on light-mid pink; left-align.
- **Severity**: medium ; **Tags**: typography, hierarchy, contrast, buttons

### F-12 Check button-label contrast on coloured buttons (white on pink fails)  (p.95, from visual)
- **Rule**: (From visual) A white (#FFFFFF), 22px Regular label on the pink "Learn more" button fails WCAG AA and AAA; a dark (#141B12) 18px Semibold label on the same pink passes both.
- **Why**: Light text on light/mid-saturated fills lacks contrast.
- **Do / Don't**: Bad: white regular label on pink. Good: dark semibold label on pink.
- **Audit check**: Measure label vs button-fill contrast ≥4.5:1; especially white text on pastel/pink/yellow/light-green buttons.
- **Restyle fix**: Switch the label to a near-black (e.g. #141B12) and increase to semibold, or darken the button fill.
- **Severity**: high ; **Tags**: buttons, contrast, accessibility

## Typography: "Things to avoid" and "Things to do" checklists (p.96-97)

### F-13 Don't use pure black (#000000) or pure white (#FFFFFF) for both headings and paragraphs  (p.96)
- **Rule**: Avoid pure #000000 / #FFFFFF as the colour of both headings and paragraphs. (Good card in p.95 uses #1B000D for headings and #5E5458 for paragraph instead of #000000 for both.)
- **Why**: Using the same extreme colour everywhere removes differentiation between content types (and is the failing pattern in the p.95 bad card).
- **Do / Don't**: Don't #000 text everywhere (bad card). Do slightly tinted near-black for headings, softer grey for paragraphs.
- **Audit check**: Text colour == #000000 or #FFFFFF for both heading and body (`text-black`, `text-white` on both) → flag.
- **Restyle fix**: Heading → near-black tint (e.g. #1B000D); body → softer dark grey (e.g. #5E5458) that still passes 4.5:1. On dark mode use off-white for headings and a dimmer light-grey for paragraphs (extension of rule, not stated).
- **Severity**: medium ; **Tags**: typography, color, contrast

### F-14 Use darker colour for headings and lighter colour for paragraphs  (p.96-97)
- **Rule**: Differentiate content types: headings in darker colour, paragraphs in lighter colour (but still accessible). Avoid the same colour for headings and paragraphs.
- **Why**: Guides the user's eye and distinguishes types of content.
- **Do / Don't**: Do heading #1B000D vs paragraph #5E5458 (p.95). Don't same colour (#000000 both).
- **Audit check**: Heading colour == paragraph colour → violation. Lightness gap should be visible while paragraph still ≥4.5:1.
- **Restyle fix**: Introduce a secondary text token for paragraphs lighter than the heading token.
- **Severity**: medium ; **Tags**: hierarchy, color, typography

### F-15 Use thicker weights for headings and thinner weights for paragraphs  (p.96-97)
- **Rule**: Headings: bold, semibold or medium. Paragraphs: regular (sometimes light). Do not use the same weight for headings and paragraphs.
- **Why**: Clearly distinguishes hierarchical elements.
- **Do / Don't**: Do heading Bold / paragraph Regular (p.95 good card). Don't heading and paragraph at same weight (bad card heading Medium vs body Regular is the weak case; hierarchy relies on size).
- **Audit check**: heading `font-weight` ≤ body `font-weight` → violation (see F-01 exception if the heading is clearly larger than body). Body weight < 400 → see F-03.
- **Restyle fix**: Headings 500-700, body 400.
- **Severity**: medium ; **Tags**: typography, hierarchy

### F-16 Don't give headings a bigger line-height than paragraphs (checklist form)  (p.96-97)
- **Rule**: "Things to avoid": bigger line-height for headings than for paragraphs. "Things to do": smaller line-height for headings and larger for paragraphs for balanced visual flow and easier scanning. (Detail and numbers in F-08.)
- **Why**: Balanced flow, easier scanning.
- **Do / Don't**: Heading 120% / paragraph 160% good; heading 160-170% / paragraph 110-120% bad.
- **Audit check**: heading LH ratio > paragraph LH ratio.
- **Restyle fix**: See F-08.
- **Severity**: medium ; **Tags**: typography, spacing

### F-17 Use sans-serif typefaces for body copy  (p.97)
- **Rule**: Prefer sans-serif for body copy: Open Sans, Inter, Roboto are generally more readable than serifs such as Times New Roman or Georgia. Fonts can still define the brand, but readability comes first.
- **Why**: Readability.
- **Do / Don't**: Do Open Sans / Inter / Roboto body. Don't Times New Roman / Georgia for body text. (Serif headings, e.g. Playfair Display, are acceptable per F-18.)
- **Audit check**: Body `font-family` resolves to a serif (Times New Roman, Georgia, `font-serif`) → flag.
- **Restyle fix**: Switch body to Inter / Open Sans / Roboto; keep serif only for display headings if brand demands.
- **Severity**: low ; **Tags**: typography

### F-18 Use no more than two fonts (ideally one family with weights and sizes)  (p.96-97)
- **Rule**: Max two different fonts. Best practice: one font with different weights and sizes. Experienced designers can pair two, e.g. Playfair Display for headings + Roboto for paragraphs. Avoid fonts that compromise aesthetics or readability.
- **Why**: Consistency, readability and aesthetics.
- **Do / Don't**: Do one family (or a deliberate heading/body pair). Don't use 3+ typefaces or decorative fonts that hurt readability.
- **Audit check**: Count distinct `font-family` values in the CSS/Figma styles: >2 → violation. Check any display/script font used for body or UI labels.
- **Restyle fix**: Consolidate to a single family (e.g. Inter) using weight/size for hierarchy; or a max of one heading font + one body font.
- **Severity**: medium ; **Tags**: typography, craft

### F-19 Give long text blocks adequate space between paragraphs  (p.97)
- **Rule**: Ensure longer text blocks have adequate space between paragraphs so they look more appealing and are easier to read. (No numeric value given.)
- **Why**: Visual appeal and readability.
- **Do / Don't**: Do clear paragraph gaps. Don't run paragraphs together with no/very little margin.
- **Audit check**: Paragraph `margin-bottom` / gap between `<p>` ≈ 0 in long-form text → violation.
- **Restyle fix**: Add paragraph spacing (e.g. around one line-height; value is my suggestion, not stated).
- **Severity**: low ; **Tags**: typography, spacing
